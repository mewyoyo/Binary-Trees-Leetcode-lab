226. Invert Binary Tree

1. Problem
Given the root of a binary tree, invert the tree (mirror it horizontally by swapping every node's left and right children), and return its root.

2. Approach
Use Depth-First Search (DFS) recursion to swap child pointers at each node:
- Base case: If root is null, return null.
- Swap children: Save root.left in a temporary TreeNode variable (temp), assign root.right to root.left, and assign temp to root.right.
- Recursive step: Recursively call invertTree(root.left) and invertTree(root.right).
- Return root.

Challenges Faced & Failed Approaches
1. Swapping left and right child references properly (TreeNode temp = root.left; root.left = root.right; root.right = temp;)
- Mistake: Struggling with the pointer swap logic, such as attempting to assign root.left = root.right and root.right = root.left directly without a temporary variable, or mixing up the order of assignments.
- Why it failed: Overwriting root.left with root.right without saving the original reference first destroys the pointer to the left subtree, causing both left and right children to point to the same right subtree.
- Fix: Stored the original left child in a temporary variable (TreeNode temp = root.left) before reassigning root.left = root.right, and then restored it via root.right = temp.

3. Time Complexity
Time Complexity: O(n)
- Each of the n nodes in the tree is visited once to swap its left and right children.

Space Complexity: O(n)
- O(n) in the worst case (skewed tree) and O(log n) on average (balanced tree) due to the recursion call stack.

4. Reflection / Improvement
- Is there a better approach? Both recursive DFS and iterative BFS run in optimal O(n) time since every node must be visited to invert the entire tree.
- Alternative: Iterative BFS using a Queue traverses the tree level-by-level and swaps children iteratively, avoiding potential recursion stack overflow on deeply skewed trees.
- Best Complexity: O(n) Time, O(n) Space (worst case) / O(log n) Space (balanced).
